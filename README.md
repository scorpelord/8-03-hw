# Домашнее задание к занятию "Микросервисы: масштабирование" - `Молоствов Андрей`

### Задание 1

### Сравнение решений для оркестрации контейнеров

**1. Kubernetes**
*   **Поддержка контейнеров:**  Да (изначально спроектирован для контейнеров, поддержка Docker, containerd, CRI-O).
*   **Обнаружение сервисов и маршрутизация запросов:**  Да (встроенные объекты Service, Ingress, kube-proxy, CoreDNS).
*   **Горизонтальное масштабирование:**  Да (ручное масштабирование через replicas).
*   **Автоматическое масштабирование:**  Да (Horizontal Pod Autoscaler на основе метрик CPU/памяти или кастомных метрик).
*   **Разделение ресурсов (внешние/внутренние):**  Да (типы сервисов: ClusterIP — внутренний, NodePort/LoadBalancer/Ingress — внешний доступ).
*   **Конфигурирование через переменные среды:**  Да (ConfigMap для обычных переменных, Secrets для чувствительных данных с поддержкой шифрования etcd).

**2. Docker Swarm**
*   **Поддержка контейнеров:**  Да (родное решение для Docker).
*   **Обнаружение сервисов и маршрутизация запросов:**  Да (встроенный DNS, routing mesh).
*   **Горизонтальное масштабирование:**  Да (команда `docker service scale`).
*   **Автоматическое масштабирование:**  Частично (ограниченные возможности, требует внешних инструментов).
*   **Разделение ресурсов (внешние/внутренние):**  Да (публикация портов, overlay сети).
*   **Конфигурирование через переменные среды:**  Да (секреты и конфиги Docker Swarm).

**3. HashiCorp Nomad**
*   **Поддержка контейнеров:**  Да (поддержка Docker, Podman, а также виртуальных машин и исполняемых файлов).
*   **Обнаружение сервисов и маршрутизация запросов:**  Требует интеграции с Consul (отдельный продукт HashiCorp).
*   **Горизонтальное масштабирование:**  Да.
*   **Автоматическое масштабирование:**  Да (Nomad Autoscaler).
*   **Разделение ресурсов (внешние/внутренние):**  Частично (требует настройки через Consul и Fabio/Envoy).
*   **Конфигурирование через переменные среды:**  Да (шаблоны и переменные, интеграция с Vault для секретов).

### Обоснование выбора (Кластеризация)

На основе сравнительного анализа в качестве основного решения предлагается использовать **Kubernetes**.

**Почему Kubernetes?**

1.  **Полное соответствие требованиям:**
    *   **Контейнеры:** Kubernetes является отраслевым стандартом для оркестрации контейнеров, поддерживая все популярные runtime (containerd, CRI-O, Docker).
    *   **Обнаружение сервисов:** Встроенный DNS (CoreDNS) позволяет сервисам находить друг друга по именам, а kube-proxy обеспечивает балансировку трафика внутри кластера.
    *   **Маршрутизация запросов:** Объект Ingress (с Ingress-контроллерами типа NGINX, Traefik) обеспечивает гибкую маршрутизацию внешнего трафика к сервисам.

2.  **Масштабирование:**
    *   **Горизонтальное масштабирование:** Простое изменение количества реплик в Deployment'е.
    *   **Автоматическое масштабирование:** Horizontal Pod Autoscaler (HPA) автоматически увеличивает или уменьшает количество реплик на основе наблюдаемых метрик (CPU, Memory или кастомных метрик из Prometheus).

3.  **Безопасность и конфигурация:**
    *   **Разделение ресурсов:** Четкое разделение через типы сервисов: ClusterIP (только внутри), NodePort/LoadBalancer/Ingress (доступ извне).
    *   **Конфигурирование:** 
        *   ConfigMap для хранения конфигурационных переменных среды.
        *   Secrets для хранения чувствительных данных (пароли, ключи доступа, токены). Secrets могут храниться в зашифрованном виде в etcd.

4.  **Экосистема:** Kubernetes имеет огромное сообщество, множество готовых решений (Helm-чарты), инструментов мониторинга (Prometheus Operator) и логирования (Loki, EFK), что делает его стандартом де-факто в индустрии.

**Почему не другие варианты?**

*   **Docker Swarm:** Значительно проще в установке и настройке, но уступает Kubernetes в возможностях автоматического масштабирования и гибкости управления сложными приложениями. Подходит для небольших проектов, но для enterprise-масштаба с микросервисной архитектурой Kubernetes предпочтительнее.
*   **HashiCorp Nomad:** Интересное решение, особенно если в компании уже используется стек HashiCorp (Consul, Vault). Однако для обеспечения всех требуемых функций (обнаружение сервисов, маршрутизация) потребуется связка нескольких продуктов (Nomad + Consul + Fabio/Envoy), что усложняет архитектуру. Kubernetes дает все эти возможности "из коробки" в одном интегрированном решении.
